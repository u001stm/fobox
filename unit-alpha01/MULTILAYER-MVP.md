# UNIT001 / Multi-Layer · 4.23.0 alpha01

Работает в существующем LUMIO, среда **UNIT · обработка α01**. Новый основной раздел — «Мультилеерный репортаж». Школьные среды, их отборы и предыдущие версии сохраняются. XMP не создаются.

## Процесс

1. Создайте проект UNIT. В «Источниках» назначьте папки Sony и каждого телефона отдельным устройствам. Исходные файлы читаются без переименования и изменения метаданных.
2. Назначьте MASTER_PHOTO, POV, FIXED, OVERHEAD и другие роли. Укажите timezone события и поправку каждого устройства: отстаёт на 7 секунд → `+7`; спешит на 12 → `-12`. QuickTime UTC включается явно для соответствующего устройства.
3. Analyze читает ExifTool/ffprobe, считает SHA-256, объединяет точные копии по содержимому, проверяет RAW/JPEG-пары. Кадры серии с одинаковым временем сохраняются раздельно. Время файловой системы не заменяет неизвестное время съёмки.
4. В хронологии доступны отдельные дорожки устройств, длинные видеополосы, просмотр, решения оставить/исключить/не решено, ручной порядок, MARK и отмена настроек/решений отбора. Материалы без достоверного времени остаются UNPLACED; время можно указать вручную. Пересчёт не стирает отбор.
5. Подготовленный внешний видеофрагмент можно связать с родительским роликом и trim-in/out. Обработанный JPEG связывается с исходной фотографией без создания дополнительного capture. Прежний раздел RAW-коррекции сохраняется.
6. «Выдача» — единая точка рабочего и финального экспорта. Build timeline создаёт реальные копии для Bridge: `001.jpg`, `001-01.mov`, `002.jpg`. Режим последовательной нумерации доступен отдельно. Финал включает только оставленные фото/видео: `001.jpg`, `002.mp4`, `003.jpg`, без пропусков.

## Контракты и время

`ml_schema.json` описывает event/devices/assets/timeline/markers/stats. Встроенный валидатор проверяет используемое подмножество JSON Schema и связи объектов; это не универсальный JSON Schema сервис.

Сохраняются исходное время, нормализованное UTC, timezone, поправка и происхождение значения. Наивное время допускается только с явным флагом предположения; неоднозначное время DST без offset отклоняется. Offset применяется один раз. Видео при равном времени следует за фотографиями; до первого фото получает якорь 000. Покрытие видео — полуинтервал [start,end); сумма длительностей и объединённое покрытие считаются отдельно. Неизвестная длительность остаётся null.

PHOTO ACTIVITY считает capture основного фотоисточника, а не количество RAW+JPEG файлов. Интервалы 5/10/30 минут или AUTO: до 90 минут — 5, до 240 — 10, иначе 30. Сохраняются нулевые интервалы, последний конец включается, частичные интервалы имеют фактический знаменатель. Пики количества и скорости разделены; для скорости сначала полные интервалы. Один кадр даёт нулевую длительность и неизвестную скорость.

## Хранение и интеграция

Используется существующий каталог LUMIO: новые таблицы `ml_projects`, `ml_assets`, `ml_analyses`; отдельная база реестра событий не создаётся. Превью — локальные копии в CACHE. Карта может отключиться: анализ и решения остаются, недоступность оригиналов показывается; для экспорта оригиналы должны быть доступны.

Каждый анализ — отдельная атомарно опубликованная папка `MULTILAYER/DATA/r000001-…/`; `DATA/current.json` указывает актуальную ревизию. TXT, JSON, CSV, SVG и PNG относятся к одной ревизии. SVG — канонический график, PNG строится из его геометрии. WORK/v001 и EXPORTS/v001 не перезаписываются. Перед копированием проверяется место, после — контрольные суммы. Отменённая/ошибочная staging-папка не считается готовой выдачей.

ULS остаётся главным реестром. Связь устанавливается явно по существующему record_id; текущая интеграция читает реестр, но не создаёт записи и не отправляет статистику автоматически. Импорт EVENT сохраняет неизвестные поля Generator и не изменяет внешний файл. Локальный UUID — рабочая ссылка до связывания, не второй номер съёмки.

Приватные отчёты могут содержать исходные пути. Публичный CLIENT/event.public.json формируется отдельным whitelist без путей, GPS, serial и MARK. Публикации в облако из нового раздела пока нет. В GitHub не входят фотографии, каталоги, runtime, модели и токены.

## Проверки и пределы alpha01

- 105 Python-тестов: успешно, один пропущен. В том числе 27 новых тестов времени, пар, активности, отбора, сохранения, экспорта, отмены и неизвестных данных.
- Сквозная проверка: два настоящих Sony ARW, две **тестовые JPEG-пары**, полученные из ранее проявленных RAW, и **синтетический MOV**. Получены два capture, один видеоматериал и финал JPEG/настоящий H.264/AAC MP4/JPEG. Изменение offset с +7 на -12 сдвигает материал ровно на 19 секунд. Оригиналы на карте не изменились.
- Браузер: три превью, два устройства, изменение offset, исключение/отмена, SVG, рабочий экспорт и сохранение после перезагрузки проверены в обеих темах. Установленный сервер 8776 отдельно проверен: три карточки, папки источников 2/2, PHOTO ACTIVITY, без ошибок страницы.
- Это не проверка настоящих файлов iPhone. Их QuickTime/codec варианты ещё нужно проверить на реальном материале.
- Bridge установлен, но фактическая сортировка и воспроизведение не подтверждены: инструмент native UI дважды завершился тайм-аутом. `bridge_verified` остаётся false. Смена расширения MOV на MP4 не используется: совместимый ролик remux через FFmpeg, несовместимый отклоняется с объяснением.
- Новые модели и зависимости автоматически не скачиваются. Готовность ExifTool/ffprobe/ffmpeg видна в источниках; можно задать путь вручную.
- Автоматический монтаж, ASR, сайт выдачи, автонарезка по часам и облачная синхронизация не реализованы. Ручные решения сохраняют приоритет.

Запуск — существующий «Запустить UNIT alpha01.bat», сервер 8776. Новый дистрибутив или ZIP для этой версии не нужен.
